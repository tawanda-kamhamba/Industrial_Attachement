1(d) Brief Background of the Problem

  • Industrial attachment connects academic learning with real workplace experience
  • Multiple stakeholders must coordinate: students, host companies, institutional supervisors, and administrators
  • At many institutions, processes still rely on paper forms, email, WhatsApp, and scattered file storage
  • This creates delays, lost documents, and poor visibility of student progress
  • The Faculty needs a central digital system to manage attachment activities at scale

2(a) What Problem Is Being Addressed?

  • Fragmented, manual management of industrial attachment programmes
  • No single platform to track registration, assumption of duty, orientation, contracts, logbooks, reports, visits, and grades
  • Difficulty assigning and monitoring students to supervisors and host companies
  • Assessment records stored separately and inconsistently across channels
  • High administrative workload and risk of incomplete or lost documentation

2(b) Why Is It Important?

  • Attachment quality depends on timely monitoring and accurate records
  • Manual processes are tedious, error-prone, and hard to scale as student numbers grow (Sulaiman et al., 2022)
  • Institutions cannot easily demonstrate programme effectiveness or produce placement statistics
  • Poor coordination frustrates students, supervisors, and industry partners
  • Digital transformation improves accountability, audit trails, and reporting

2(c) Who Is Affected by the Problem?

  • Students — delayed feedback, unclear requirements, lost submissions
  • Institutional Supervisors — difficulty tracking assigned students and visits
  • Company Supervisors — informal grading and communication channels
  • Faculty Administrators — heavy workload counting registrations, placements, and reports
  • Host Companies — limited structured feedback mechanisms
  • The Institution — inability to monitor attachment quality at faculty scale

3(a) General Objective

  • To develop the Industrial Attachment Management System (IAMS)
  • A role-based web application that centralises industrial attachment management
  • Supports four stakeholder groups: students, institutional supervisors, company supervisors, and administrators
  • Replaces fragmented manual processes with one integrated digital platform
  • Enables monitoring, scheduling, assessment, and reporting from a single source of truth

3(b) Specific Objectives — Student Module

  • Secure student authentication using registration number and password
  • Instructions page guiding students through all attachment processes
  • Industrial registration and assumption of duty submission
  • Orientation checklist, contract upload (PDF), and final report upload
  • Weekly electronic logbook (e-logbook) for task and skill recording
  • Visit date selection after supervisor publishes available dates
  • Direct supervisor assignment requests and issue reporting to assigned supervisors

3(b) Specific Objectives — Supervisor & Admin

  • Institutional supervisor dashboard for assigned students and document review
  • Visit scheduling: publish dates → students select → notifications sent
  • Visit grading (Visit 1 & 2), e-logbook marks, report marks, and final grade computation
  • Password-protected company and visiting supervisor assessment forms
  • Admin dashboard with analytics, supervisor assignment, and document oversight
  • In-system notifications for visits, logbook comments, contracts, and assignment requests

3(c) Expected Outcomes

  • A working web prototype replacing paper-based attachment processes
  • Centralised MySQL database of student attachment records
  • Faster supervisor monitoring and grade aggregation
  • Real-time admin analytics (registrations, faculty distribution, regional placements)
  • Improved audit trail for visits, submissions, and assessments
  • Foundation for future integration with institutional systems (e.g. Emhare)

4(a) System Architecture Diagram

  • Three-tier architecture:
  • Presentation: React 18 SPA (TypeScript, Vite, Tailwind CSS)
  • Application: PHP REST-style JSON API with session-based RBAC
  • Data: MySQL relational database (IASMS)
  • Deployment: XAMPP (local) / InfinityFree (hosted demo)
  • Flow: Browser → React (/iasms/app) → PHP API (/iasms/api) → MySQL + file storage

  • Student — index number + password

  • Administrator — admin password
  • Onboarding guard blocks attachment modules until registration and assumption are complete
  • Industrial registration captures programme, faculty, level, and session
  • Assumption form captures company, region, supervisor contacts, attachment period

5(e) AI / ML Functionality

  • Not applicable to this project
  • IAMS is an administrative information system focused on workflow automation and record management
  • Evaluation criteria: functional correctness, usability, response time, and role-appropriate access
  • No machine learning models, training data, or predictive analytics were implemented
  • Future work: predictive analytics on placement success or automated logbook quality checks

5(f) Mobile App Functionality

  • No native mobile application (Android/iOS) was developed
  • IAMS is a responsive web application accessible on desktop and mobile browsers
  • Tested on Chrome, Edge, Firefox (Windows) and mobile viewport on Android browser
  • Tailwind CSS responsive layouts support phone and tablet use during field attachment
  • Students can complete logbooks and upload documents from mobile browsers in the field

5(g) Error Handling & Security — Conclusion

  • RBAC: PHP session roles on all protected API endpoints
  • Frontend guards: ProtectedRoute, StudentOnboardingGuard
  • File validation: allowed extensions for contracts (PDF) and reports
  • SQL injection mitigation: input escaping on API inputs
  • HTTPS on production host; JSON error responses on API failures
  • Limitations: email notifications and full password hashing scoped out of prototype
  • Conclusion: IAMS successfully centralises industrial attachment management using React + PHP + MySQL
  • All four roles have dedicated interfaces and permissions
  • Core modules tested and validated through UAT
